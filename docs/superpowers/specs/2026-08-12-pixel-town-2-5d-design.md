# 解忧小镇东方像素 2.5D 升级设计规格

日期：2026-08-12  
状态：已确认，待实施计划  
适用范围：公共小镇地图、烦恼详情页、后台地图编辑器与坐标迁移

## 1. 决策摘要

现有小镇是一张 `1600 × 900` SVG 背景图，上面叠加绝对定位的 React 链接。它支持拖动、缩放和内容访问，但视觉仍是平面矢量画卷。

本次升级把公共地图改造成“东方山林灯火”主题的原创像素 2.5D 世界：中央是解忧驿站，左侧为林场，右侧为牧场。地图保留点击生命进入烦恼详情的内容浏览方式，不增加角色自由行走。溪流、树叶、灯火、萤火虫和动物待机提供低频环境动画。

技术采用 Next.js / React 与 PixiJS 的混合架构：React 继续管理服务端取数、业务状态、路由、正文、工具栏和无障碍链接；PixiJS 只负责场景绘制、动画、相机和命中检测。`@pixi/react` 被封装在单独的客户端场景边界内，避免业务组件依赖渲染器实现。

## 2. 已确认的产品选择

- 目标是视觉上的 2.5D，不是真 3D。
- 访客不控制角色移动，核心操作仍是浏览地图并点击生命。
- 第一阶段改造小镇地图与烦恼详情页；其他公共页面和后台外观不做全站像素化。
- 美术方向为原创“东方山林灯火”，不复制《星露谷物语》的素材、角色、建筑或配色。
- 主要展示设备是电脑浏览器；手机保留完整的点击与阅读能力。
- 动态等级为“会呼吸的世界”：低频环境和待机动画，不加入昼夜、天气或持续巡游。
- 地图结构采用中央解忧驿站，左接林场、右接牧场。
- 素材采用混合生产：先建立规范和可运行素材，后续允许像素画师按相同接口精修替换。
- 树木类生命只放在林场，动物类生命只放在牧场；驿站不摆放烦恼生命。

## 3. 目标与非目标

### 3.1 目标

1. 让地图在不引入自由行走的前提下具有明确的空间层次、遮挡关系和生命感。
2. 保持现有烦恼、生命、成长阶段、回应数量和详情路由的业务闭环。
3. 让鼠标、键盘、读屏和减少动态效果用户都能访问同一批内容。
4. 将美术和动画做成数据驱动资源，支持后续画师替换而无需改业务代码。
5. 安全迁移现有地图位置，并提供预览、幂等执行和回退依据。
6. 渲染失败时仍能通过静态全景和完整列表浏览全部公开烦恼。

### 3.2 非目标

- 角色自由行走、碰撞、任务和完整游戏循环。
- Three.js 真 3D、体素模型或可旋转镜头。
- 昼夜、天气、季节系统和动物长距离巡游。
- 实时多人、评论、点赞、排行榜或付费。
- 全站像素化或后台视觉重做。
- 首版素材上传、在线精灵编辑器或第三方素材市场。

## 5. 体验与空间设计

### 5.1 地图空间

场景使用 `1536 × 864` 逻辑世界尺寸，对应 `48 × 27` 个 `32 × 32` 基础网格，保持 16:9。

- 左侧林场：较密的青绿树冠、林间小径和树木类烦恼。
- 中央驿站：主建筑、公告牌、木桥、暖灯和主要引导路径。
- 右侧牧场：开阔草地、矮树、围栏和动物类烦恼。
- 溪流与石径贯穿三部分，作为视觉和导航线索。
- 远山、地形、结构、生命和环境效果具有固定的层级边界。

烦恼数量在首轮约为十个，因此生命集中分布在林场和牧场的可见区域，避免长卷地图造成稀疏感。驿站只作为叙事和导航中心，不增加新的内容实体。

### 5.2 地图交互

- 地图初始显示完整全景。
- 拖动超过约 6 CSS 像素才进入平移，避免点击误触。
- 滚轮以指针位置为中心缩放，缩放范围为 `0.8–2.4`。
- “回到全景”恢复默认相机。
- 悬停生命显示烦恼标题、生命名称、成长阶段和已发布回应数。
- 点击生命直接进入详情，不增加二次确认面板。
- 键盘聚焦生命时相机自动平移，使其进入安全可视区；`Enter` 打开详情，`Escape` 关闭悬浮信息。
- 手机支持单指拖动、点击和双指缩放，但桌面体验优先。

### 5.3 烦恼详情页

详情页继续使用 React 和语义化 HTML。像素改造只影响主视觉和装饰框架：

- 当前成长阶段的生命使用大幅像素主视觉。
- 可选低频待机动画使用 CSS 精灵表，不启动完整 PixiJS 应用。
- 正文、成长说明、观点卡片和旅人链接保持清晰的阅读布局。
- 动画关闭或素材失败时显示同阶段静态帧。

## 6. 技术架构与组件边界

### 6.1 三层结构

#### 服务端与数据层

`TownPage` / `TownScene` 继续在服务端读取已发布烦恼、生命、成长阶段和位置。新增 `WorldAdapter`，把数据库结果转换为可序列化、只读的 `TownWorldModel`。

#### React 体验层

`TownExperience` 管理：

- PixiJS 动态加载状态。
- 当前悬停或聚焦的生命。
- 工具栏与相机命令。
- 路由跳转。
- DOM 热点与完整列表。
- 错误边界与静态降级。

#### PixiJS 场景层

`PixiTownCanvas` 是客户端动态加载边界，内部使用 `@pixi/react` 和 `pixi.js`。它只负责：

- 纹理加载与场景绘制。
- 精灵动画和环境效果。
- 相机平移、缩放和轻微视差。
- 遮挡排序和点击命中。
- 画布尺寸同步与生命周期释放。

依赖在实施时锁定经过验证的 PixiJS v8 与 React 19 兼容版本，不使用未固定版本范围。

### 6.2 场景图层

1. `BackdropLayer`：远山、天空和雾。
2. `TerrainLayer`：草地、道路和溪流。
3. `StructureLayer`：驿站、木桥、公告牌和围栏。
4. `LifeLayer`：树木和动物生命。
5. `AmbientLayer`：灯火、萤火虫、落叶和水面动画。
6. `InteractionLayer`：PixiJS 命中区域；不承载文字。

### 6.3 硬边界

- PixiJS 不访问数据库、不调用业务 API、不直接控制 Next.js 路由。
- React 不逐帧驱动环境或精灵动画。
- 正文、工具栏、悬浮信息和无障碍链接不绘制到 Canvas。
- 业务数据只通过 `TownWorldModel` 单向传入场景。
- 公共场景只发出 `hoverLife(id | null)`、`selectLife(id)`、`cameraChanged(view)` 和错误事件。
- 编辑模式使用独立的 `TownEditorBridge`：场景发出 `beginMove(id)`、`previewPlacement({ id, x, y })` 和 `endMove(id)`；React 保存草稿位置并通过 `setDraftPlacement`、`focusLife`、`commitPlacement`、`cancelPlacement` 命令回写场景。方向键移动由 DOM 编辑控件产生相同的草稿命令。
- 拖动结束只更新 React 草稿；只有主理人明确点击保存且 API 成功后，`commitPlacement` 才把草稿标记为已保存。场景不直接调用保存 API。
- 页面卸载时释放 Ticker、事件监听、Canvas 和非共享纹理。

### 6.4 建议文件边界

```text
src/features/town/
├─ town-scene.tsx                 # 服务端取数与外壳
├─ town-experience.tsx            # React 客户端体验层
```

管理端复用 `world-model`、`world-adapter`、`asset-manifest` 和场景图层，不复制第二套地图实现。

## 7. 场景数据流与事件流

```text
数据库公开数据
  → WorldAdapter
  → TownWorldModel
  → TownExperience
  → PixiTownCanvas / DOM InteractionOverlay

Pixi 命中或 DOM 热点
  → TownExperience callback
  → Next.js 路由
  → 烦恼详情页
```

`TownWorldModel` 至少包含：

```ts
type TownWorldModel = {
  layoutVersion: 2;
  width: 1536;
  height: 864;
  lives: Array<{
    worryId: string;
    slug: string;
    title: string;
    responseCount: number;
    zone: 'forest' | 'pasture';
    x: number;
    y: number;
    depthOffset: number;
    assetId: string;
    growthStage: number;
  }>;
};
```

Canvas 负责视觉命中，DOM 链接负责可访问目标。两者共享同一生命 ID 和相机投影函数，避免维护两套坐标算法。

## 8. 数据模型与坐标迁移

### 8.1 MapPlacement

保留现有字段并新增版本：

```prisma
model MapPlacement {
  id            String @id @default(cuid())
  worryId       String @unique
  zone          String
  x             Float
  y             Float
  zIndex        Int    @default(0)
  layoutVersion Int    @default(1)
  worry         Worry  @relation(fields: [worryId], references: [id], onDelete: Cascade)
}
```

- `x` 和 `y` 继续是 `0–100` 归一化坐标。
- v2 渲染换算为 `worldX = x / 100 × 1536`、`worldY = y / 100 × 864`。
- 主要遮挡顺序来自精灵脚底 `worldY`；`zIndex` 作为小范围 `depthOffset` 使用。
- `layoutVersion` 允许旧坐标在部署过渡期继续由 v1 适配器解释。

### 8.2 区域规则

- `LifeAsset.type === 'tree'` 时服务端派生 `zone = 'forest'`。
- `LifeAsset.type === 'animal'` 时服务端派生 `zone = 'pasture'`。
- v2 区域边界使用版本化多边形配置，同时在客户端预览和服务端保存时校验。
- 管理端不再提交可信的 `zone`；保存服务根据烦恼关联的生命类型派生区域。

### 8.3 迁移流程

1. 只读导出所有 v1 位置为带时间戳的 JSON 快照。
2. `town-layout-v1` 为林场和牧场分别声明旧版源矩形；`town-layout-v2` 声明新版目标安全矩形、区域多边形及其质心。这些常量随代码版本提交，不从当前数据动态推断。
3. 对每个 v1 点先钳制到对应源矩形，再计算矩形内的相对坐标 `u / v`，最后线性映射到对应目标安全矩形。
4. 若映射点落在目标区域多边形之外，将其投影到“目标多边形质心 → 映射点”射线与边界的最近交点，并沿射线向质心内缩半个基础网格（16 个逻辑像素）。多边形边按配置顺序处理，交点相同时取序号最小的边，保证结果确定。
5. 转换后的世界坐标重新归一化为 `0–100`，并按生命 ID 排序生成预览和机器可读差异清单。
6. 在后台预览转换结果，不写数据库。
7. 主理人逐项拖动修正并确认。
8. 在事务中写入确认坐标并把 `layoutVersion` 更新为 `2`。
9. 迁移脚本只选择 `layoutVersion = 1`，因此重复执行不会再次移动数据。

部署过渡期内 `WorldAdapter` 同时支持 v1 和 v2。回退依据是迁移前 JSON 快照和数据库备份；恢复只针对明确的迁移记录，不执行广泛覆盖。

## 9. 后台地图编辑器

后台编辑器升级为复用公共场景的编辑模式：

- 左侧选择烦恼，查看生命素材、类型和成长阶段。
- 区域由生命类型自动决定并显示为只读信息。
- 右侧显示最终地图、区域边界、网格和全部已摆放生命。
- 支持点击空地放置、拖动已有生命和方向键精细移动。
- 精灵脚底锚点吸附到逻辑像素网格，避免半像素模糊。
- 编辑模式关闭环境动画，仅保留必要的选择与定位反馈。
- 未保存位置有明确轮廓；只有保存成功才更新服务端状态。
- API 校验管理员、同源请求、烦恼与素材关系、有限数值、布局版本和区域多边形。
- 保存成功后重新验证 `/town` 和 `/admin/map`。

保存请求包含 `worryId`、`x`、`y` 和 `layoutVersion: 2`。服务端根据 `worryId` 查询关联的 `LifeAsset` 并派生 `zone`，忽略客户端对区域的任意声明。

## 10. 像素素材规范

### 10.1 基础规范

- 基础地形网格：`32 × 32` 逻辑像素。
- 树木画布：`64 × 96`。
- 动物画布：`64 × 48`。
- 建筑按网格整数倍设计。
- 所有生命使用统一脚底锚点。
- 素材画布、精灵局部缩放和场景摆放使用整数逻辑像素；精灵局部缩放通常固定为 `1`，不得用非整数局部缩放修正尺寸。
- 相机相对“适配全景”的基础缩放可以在 `0.8–2.4` 范围内连续变化，以支持指针中心缩放；所有纹理始终使用最近邻采样。连续相机缩放只改变整棵场景树，不改变素材网格、锚点或世界坐标。
- 核心调色板约 24–32 色，以青绿、土褐、米色和暖灯黄为主。
- 光源方向、阴影方向、俯视角和轮廓密度在美术圣经中固定。

### 10.2 资源目录

```text
public/town/pixel/v2/
├─ terrain/
├─ structures/
├─ life/<asset-id>/stage-{0..3}.png
├─ ambient/
├─ atlases/
└─ manifest.json
```

`manifest.json` 描述纹理路径、帧尺寸、帧序列、帧时长、锚点、默认缩放、命中区域和减少动态效果时的静态帧。清单在构建测试和运行初始化时使用 Zod 校验。

`LifeAsset.growthThresholds` 继续决定成长阶段。v2 清单是像素场景的视觉资源来源；现有 `growthStagePaths` 在过渡期保留为静态降级路径，并可在切换完成后指向对应 v2 静态帧。

### 10.3 授权要求

- 不使用从商业游戏中提取的精灵、瓦片、角色或建筑。
- 每项外部参考和最终素材记录来源、作者、许可和修改情况。
- 画师交付必须包含项目所需的商用授权。
- AI 辅助图片只用于概念或首版生产输入；进入项目的最终精灵必须经过像素网格、透明边缘、调色板和一致性检查。

## 11. 动画系统

动画由清单声明并由 PixiJS 统一 Ticker 驱动：

- 溪流：3–4 帧低速循环。
- 树叶：2–3 帧间歇摇动。
- 灯火：3 帧轻微明暗变化。
- 萤火虫：少量粒子，随机错开时间。
- 动物：2–4 帧呼吸、眨眼或低头，动作之间保留静止间隔。
- 成长切换：一次短过渡，不循环。

同类生命使用确定性随机种子错开动画起点。浏览器标签页隐藏、地图离屏或页面进入后台时暂停 Ticker。`prefers-reduced-motion` 开启后关闭环境循环、视差和成长过渡，只保留静态关键帧。

缺少非关键帧时回退到该成长阶段的静态帧；缺少单个生命纹理时显示统一像素剪影；关键清单无效时不初始化 PixiJS。

## 12. 加载与性能

### 12.1 渐进加载

1. 服务端立即输出页面标题、说明、静态像素全景和完整烦恼列表。
2. 地图进入可视区域后动态加载 PixiJS 客户端分包。
3. 先加载地形、结构和当前成长阶段的生命纹理。
4. 场景可操作后，在浏览器空闲阶段启动环境纹理和动画。
5. 未显示的成长阶段不进入地图首屏请求。

### 12.2 性能预算

- 参考测试场景为生产构建、Chrome 当前稳定版、Windows 11、`1440 × 900` 视口、DPR 上限 `2`、十个生命及全部首版环境动画。验收报告记录实际 CPU、GPU、内存和浏览器版本；参考设备下限为 4 个逻辑 CPU、8 GB 内存和近五年集成显卡。
- 性能脚本先预热 5 秒，再执行 30 秒的固定平移、缩放和悬停序列；目标平均帧率不低于 55 FPS，95% 的帧耗时不超过 33.3 ms，视觉目标仍为显示器刷新率下的 60 FPS。
- 首屏必要像素纹理压缩后目标不超过约 2 MB。
- PixiJS 作为独立动态分包，不进入其他页面的公共首屏包。
- 渲染分辨率的设备像素比上限为 `2`。
- 地形、建筑和环境素材使用纹理图集，减少请求与纹理切换。
- 自动降级忽略最初 2 秒预热，随后使用连续 3 秒滚动窗口计算平均帧率；连续两个窗口低于 45 FPS 时关闭视差和萤火虫。本次会话不自动重新开启，保留点击、相机和基础生命待机。

性能预算在正式构建产物和真实浏览器中测量，不依赖开发模式结果。

## 13. 无障碍

- Canvas 标记为装饰性渲染层，不作为唯一交互来源。
- 每个生命都有 React/DOM 链接，与视觉精灵共享同一相机投影函数。
- DOM 链接提供烦恼标题、生命名称和回应数量。
- 键盘聚焦具有可见轮廓，不只依赖发光或颜色。
- 工具栏、悬浮信息和详情正文均为普通 HTML。
- 地图下方始终保留完整烦恼列表。
- 减少动态效果用户获得静态但功能完整的体验。
- 触摸目标和键盘顺序由自动化测试与人工检查共同验证。

## 14. 异常与降级

- 单个动画帧失败：使用同阶段静态帧。
- 单个生命纹理失败：显示统一剪影，DOM 链接继续工作。
- 环境素材失败：关闭对应装饰效果。
- 资源清单无效或 PixiJS 初始化失败：保留静态全景和完整列表，不显示空白画布。
- 动态分包加载失败：显示一次显式“重试加载地图”，内容无需等待重试。
- 坐标无效：忽略该视觉摆放，并在后台显示可操作告警。
- 运行错误记录资源 ID、场景版本和阶段，不记录访客敏感内容。

核心原则：视觉可以降级，烦恼和真人观点不能被阻断。

## 15. 测试策略

### 15.1 单元测试

- v1 / v2 坐标转换和幂等迁移。
- 区域多边形与树木、动物区域约束。
- 世界坐标换算和 `y + depthOffset` 排序。
- 相机缩放、平移、全景重置和拖动阈值。
- 资源清单、动画帧、锚点和降级资源校验。
- 减少动态、离屏暂停和低帧率降级策略。

### 15.2 组件测试

- 静态预览、加载、就绪、错误和重试状态。
- DOM 热点与场景模型使用相同坐标。
- 拖动不会触发生命链接。
- 键盘聚焦、悬浮信息和路由事件。
- `TownEditorBridge` 的拖动草稿、取消、保存失败回滚、保存成功提交和方向键移动。
- 动画关闭后内容和操作保持完整。
- 详情页显示正确的生命和成长阶段。

### 15.3 端到端测试

- 进入小镇、拖动、缩放并打开烦恼。
- 键盘浏览并进入详情。
- PixiJS 初始化失败后通过列表完成浏览。
- 后台拖动、保存、刷新后位置不变。
- v1 坐标预览、迁移、重复执行保护和回退依据。
- 地图与列表展示相同的已发布烦恼。

### 15.4 视觉与性能检查

- 截图测试固定动画帧，避免随机抖动。
- 桌面主尺寸为重点，并补充手机降级尺寸。
- 检查精灵模糊、锚点偏移、遮挡错误和文字重叠。
- 检查纹理预算、动态分包、帧率和页面离开后的资源释放。
- 阶段门槛运行完整测试、类型检查、Lint、生产构建和相关端到端测试。

## 16. 阶段性交付

### 阶段 1：灰盒世界

完成引擎、相机、三分区、测试精灵、DOM 热点和降级外壳。用户确认空间密度和交互后进入下一阶段。

### 阶段 2：核心场景美术

完成地形、远山、驿站、木桥、公告牌、溪流、调色板和基础环境效果。用户确认整体气质后再批量制作生命。

### 阶段 3：生命与详情页

完成现有生命的四个成长阶段、低频待机和详情页像素主视觉。逐一核对生命、烦恼和成长关系。

### 阶段 4：后台与迁移

完成所见即所得编辑器、坐标快照、迁移预览、确认写入和回退依据。使用真实数据核对全部位置。

### 阶段 5：优化与交付

完成性能、无障碍、异常降级、响应式、视觉回归、端到端测试和授权清单检查。

## 17. 协作方式

用户不需要亲自绘制素材，但需要：

1. 提供 5–10 张山林、木屋、石桥、乡镇灯火等气质参考图。
2. 列出必须出现和不能出现的东方元素，避免泛古风。
3. 在灰盒地图、首套素材和完整场景三个节点集中反馈。
4. 每轮优先指出最影响气质的三项问题。
5. 若后续聘请画师，使用本项目美术圣经、模板和授权要求作为交付标准。

开发方负责美术圣经、模板、可运行素材、接入、自动校验、资源清单和测试。画师后续只替换符合清单的 PNG / 精灵表，不改变代码接口。

## 18. 风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 初版素材风格不一致 | 先锁定调色板、透视、锚点和首套样例，再批量制作 |
| Canvas 与 DOM 热点漂移 | 共享相机投影函数，并对多缩放级别做组件和截图测试 |
| PixiJS 增加首屏体积 | 动态分包、进入视口后加载、静态预览先显示 |
| 环境动画影响阅读或性能 | 低频动画、统一暂停、减少动态和低帧率自动降级 |
| 坐标迁移造成错位 | 快照、预览、版本字段、幂等脚本、逐项确认 |
| 外部素材存在版权问题 | 授权清单、禁止游戏提取素材、画师商用授权 |

## 19. 完成标准

以下条件全部满足才算完成：

1. 所有现有公开烦恼正确出现在新版林场或牧场。
2. 驿站、地图和详情页形成统一的东方像素田园体验。
3. 四个成长阶段与已发布观点数量正确对应。
4. 拖动、缩放、点击、键盘和全景重置均通过验证。
5. 近期主流电脑达到目标流畅度，且性能预算有构建与浏览器证据。
6. 动画关闭、资源缺失或 Canvas 完全失败时全部内容仍可访问。
7. 键盘、读屏和减少动态效果均有等价路径。
8. 后台能够摆放、保存、刷新并恢复相同位置。
9. 旧坐标具有快照、预览、幂等迁移和回退依据。
10. 素材来源和商用授权可追溯。
11. 单元测试、组件测试、端到端测试、类型检查、Lint 和生产构建全部通过。
